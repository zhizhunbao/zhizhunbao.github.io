              2.2 Communication between Nodes and the Control Plane
              节点与控制平面之间的通信              		 (context) "Kubernetes has a "hub-and-spoke" API pattern." （语境）Kubernetes 采用“中心辐射”式的 API 模式。 The Kubernetes Authors, n.d., "Node to Control Plane", para. 1
              2.2.1 Control plane to node
              控制平面到节点              		 "There are two primary communication paths from the control plane (the API server) to the nodes." 有两条主要的通信路径，从控制平面（API 服务器）到节点。 The Kubernetes Authors, n.d., "Control plane to node", para. 1
              proxy
              代理              		 (context) "The second is from the API server to any node, pod, or service through the API server's proxy functionality." （语境）第二条是从 API 服务器到任一节点、Pod 或服务，经由 API 服务器的代理功能。 The Kubernetes Authors, n.d., "Control plane to node", para. 1
              SSH tunnels
              SSH 隧道              		 "Kubernetes supports SSH tunnels to protect the control plane to nodes communication paths." Kubernetes 支持 SSH 隧道来保护控制平面到节点的通信路径。 The Kubernetes Authors, n.d., "SSH tunnels", para. 1
              Konnectivity service
              Konnectivity 服务              		 "As a replacement to the SSH tunnels, the Konnectivity service provides TCP level proxy for the control plane to cluster communication." 作为 SSH 隧道的替代，Konnectivity 服务提供 TCP 层代理，用于控制平面到集群的通信。 The Kubernetes Authors, n.d., "Konnectivity service", para. 1

              References
