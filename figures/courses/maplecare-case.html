1.6 Business Drivers for Cloud Migration
Reduce Data Center Risk & Cost
SAN end-of-lifeCurrent SAN is near end-of-life.
ContractsRenewing hardware and support contracts is expensive.
Power and coolingData center power and cooling costs are rising.
Improve Availability & Resilience
Single point of failureSingle data center = single point of failure.
Limited DRLimited DR strategy: backups stored offsite, but no secondary site for failover.
Enable Innovation
AnalyticsExplore analytics for patient outcomes.
Mobile appsAdd mobile apps for patients (appointment reminders, telehealth).
Standardize & Simplify IT
Fewer technologiesReduce number of technologies and custom scripts.
IaC and automationMove towards Infrastructure as Code and automated deployments.
Cloud-firstAlign with “cloud-first” strategy for new projects.
1.7 Migration Goals & Scope
Plan
The Board approves a plan to move most workloads to the cloud over 24–30 months
Goals
DecommissionDecommission the on-prem data center by the end of the program (except for a minimal footprint if needed).
High availabilityAchieve high availability for EMR and patient portal.
Patient portalModernize the patient portal to a scalable, cloud-native architecture.
Central controlsIntroduce centralized logging, monitoring, and security controls in the cloud.
Backup and DRImplement a robust backup and DR strategy in the cloud (across regions if possible, still within Canada).

How
1.10 Target Cloud Architecture (High-Level Vision)
1. Landing Zone Approach
Central environmentCentral, standardized cloud environment
SubscriptionsMultiple subscriptions/accounts for separation (e.g., Prod / Non-prod).
Network modelHub-and-spoke or VNet/VPC peering model.
Centralized controlsCentralized security, identity, and logging.
2. Identity & Access
Cloud identityUse cloud identity (e.g., Entra ID/Azure AD) as primary identity provider.
Hybrid identityIntegrate with on-prem AD for a while (hybrid identity).
RBACImplement role-based access control (RBAC) for admins and apps.
3. Networking
Hybrid connectivityEither site-to-site VPNs or private dedicated connectivity.
Firewalls and NSGsFirewalls and network security groups in the cloud.
SegmentationSegmentation between tiers (web, app, data).
4. Application Strategies (6/7 Rs)
EMRLikely Rehost (lift-and-shift) initially with minimal changes. Later, possibly Refactor parts (e.g., reporting) to PaaS.
Patient PortalStrong candidate for Refactor/Rebuild into a cloud-native web app with managed database.
File Servers & IntranetConsider Replatform to cloud file services or SharePoint Online.
Legacy, low-value appsSome may be Retired instead of migrated.
5. Data, Backup & DR
BackupUse cloud-native backup and snapshot solutions.
Geo-redundant storageGeo-redundant storage (across Canadian regions) for DR.
RPO/RTODefine RPO/RTO for each workload and design accordingly.
6. Security & Governance
Central policiesEncryption at rest and in transit. Key management (KMS/Key Vault). Logging, SIEM integration, and alerting.
GuardrailsGuardrails for resource deployment (naming, tagging, allowed regions).
7. Operations & Automation
IaCUse Infrastructure as Code (e.g., Bicep/Terraform/CloudFormation) for: Network, resource groups, security policies. App infrastructure deployments.
PipelinesAutomated pipelines for application updates.
AutomationAutomated patching, scaling, and monitoring alerts.
1.11 Migration Phases
1. Assessment & Discovery
InventoryInventory all workloads, dependencies, and data flows.
Classify appsClassify apps (6/7 Rs).
RisksIdentify technical and business risks.
2. Landing Zone & Foundation
FoundationBuild identity, networking, security baseline, and subscriptions/accounts.
ConnectivitySet up connectivity from clinics to cloud.
3. Pilot Migrations
Non-critical appsStart with non-critical apps (e.g., test environment for EMR, small internal tools).
ValidationValidate performance, monitoring, and backup.
4. Core Workload Migrations
EMRMigrate EMR and database with a carefully planned cutover.
PACSMigrate PACS storage and archive.
Patient portalModernize and migrate patient portal.
5. Optimization & Decommission
Right-sizingRight-size resources, enable autoscaling where appropriate.
CostEvaluate cost optimization opportunities.
DecommissionDecommission on-prem workloads and hardware.
