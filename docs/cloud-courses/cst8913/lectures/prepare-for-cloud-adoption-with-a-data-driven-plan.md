# Prepare for cloud adoption with a data-driven plan

Study notes on [Microsoft Learn module (retired)](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment), which CST8913 Cloud Migration (Algonquin College, Fall 2026) uses in week 4. Each section follows one part of the source. Start from the figure: the framed terms are the ones to learn, and the table below it defines them in the same order, each with a citation linked to the passage.

## [Evaluate the digital estate](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#evaluate-the-digital-estate)

![Diagram: Evaluate the digital estate](media/prepare-for-cloud-adoption-with-a-data-driven-plan-1.png)

| Term | Definition | 中文解释 | Source |
|---|---|---|---|
| **digital estate** (数字资产) | "For each of these outcomes, the first step starts with a clear understanding of the assets (applications, data, and VMs) you are responsible for today. Those assets collectively are referred to as your digital estate." | 数字资产就是一个组织现在手里所有的 IT 资产：应用、数据和虚拟机。规划上云的第一步就是把它盘清楚。 | [Microsoft, 2022, "Understand your digital estate" section, para. 1](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#understand-your-digital-estate:~:text=For%20each%20of%20these%20outcomes%2C%20the%20first%20step%20starts) |
| **Azure Migrate appliance** (Azure Migrate 设备（发现用虚拟机）) | Defined on [What is Azure Migrate?](what-is-azure-migrate.md#decide-plan-execute). | 装在本地机房的一台轻量虚拟机，负责收集服务器的配置和性能数据并持续发给 Azure Migrate；评估的数据都靠它。 | See that page |
| **agentless discovery** (无代理发现) | "Azure Migrate uses a lightweight Azure Migrate appliance to perform agentless discovery of on-premises VMware VMs, Hyper-V VMs, other virtualized machines, and physical servers. Continuous discovery collects machine configuration information, and performance metadata, as well as application data." | 无代理发现就是不用在每台服务器上装软件，只靠一台 Azure Migrate 设备远程收集服务器的配置、性能和应用信息。部署快，对业务服务器没有打扰。 | [Microsoft, 2022, "Workloads in use" section, para. 1](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#workloads-in-use:~:text=Azure%20Migrate%20uses%20a%20lightweight%20Azure%20Migrate%20appliance%20to) |
| **Azure Migrate project** (Azure Migrate 项目) | "A project is used to store discovery, assessment, and migration metadata collected from the environment you're assessing or migrating." | 项目是 Azure Migrate 的工作容器，存放发现、评估和迁移的数据；所有迁移工作都从建项目开始。 | [Microsoft, n.d., para. 2](https://learn.microsoft.com/en-us/azure/migrate/quickstart-create-project?view=migrate#:~:text=A%20project%20is%20used%20to%20store%20discovery%2C%20assessment%2C%20and) |
| **group (Azure Migrate)** (分组（服务器组）) | "With your application inventory and dependency analysis done, you can create high-confidence groups of servers and start assessing them." | 分组就是把要一起评估、一起迁移的服务器放进同一个组。通常按依赖分析的结果来分，互相依赖的放一组。 | [Microsoft, 2022, "Dependencies between workloads" section, para. 1, sentence 5](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#dependencies-between-workloads:~:text=With%20your%20application%20inventory%20and%20dependency%20analysis%20done%2C%20you) |

## [Readiness and suitability analysis](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis)

![Diagram: Readiness and suitability analysis](media/prepare-for-cloud-adoption-with-a-data-driven-plan-2.png)

| Term | Definition | 中文解释 | Source |
|---|---|---|---|
| **Ready for Azure** (可迁移（Azure 就绪）) | "Ready for Azure: Machines can be migrated as-is to Azure, without any changes." | 评估结果的一类：这台机器不用改就能直接搬到 Azure。通常最先迁这一类。 | [Microsoft, 2022, "Readiness and suitability analysis" section, bullet 1](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis:~:text=Ready%20for%20Azure%3A%20Machines%20can%20be%20migrated%20as%2Dis%20to%20Azure) |
| **Conditionally ready for Azure** (有条件可迁移) | "Conditionally ready for Azure: Machines can be migrated to Azure, but need minor changes in accordance with the remediation guidance provided in the assessment." | 评估结果的一类：能搬，但要先按评估给的修复建议做一些小改动。 | [Microsoft, 2022, "Readiness and suitability analysis" section, bullet 2](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis:~:text=Conditionally%20ready%20for%20Azure%3A%20Machines%20can%20be%20migrated%20to) |
| **Not ready for Azure** (不可迁移（未就绪）) | "Not ready for Azure: Machines can't be migrated to Azure as-is. Issues must be fixed in accordance with remediation guidance before migration." | 评估结果的一类：照原样搬不过去，必须先把问题修好再迁。 | [Microsoft, 2022, "Readiness and suitability analysis" section, bullet 3](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis:~:text=Not%20ready%20for%20Azure%3A%20Machines%20can%27t%20be%20migrated%20to) |
| **Readiness unknown** (就绪性未知) | "Readiness unknown: Azure Migrate can't determine machine readiness, because of insufficient metadata." | 评估结果的一类：收集到的信息不够，Azure Migrate 判断不了能不能迁。要补充数据后再评估。 | [Microsoft, 2022, "Readiness and suitability analysis" section, bullet 4](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis:~:text=Readiness%20unknown%3A%20Azure%20Migrate%20can%27t%20determine%20machine%20readiness) |
| **performance-based sizing** (按性能定规格) | "The performance-based sizing option in Azure Migrate assessments helps you to right-size VMs, and should be used as a best practice for optimizing workloads in Azure." | 按性能定规格就是根据服务器过去实际用了多少 CPU 和内存来推荐 Azure 规格。往往比原来的配置小，更省钱，是推荐做法。 | [Microsoft, 2022, "Get compute costs" section, para. 1](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#get-compute-costs:~:text=The%20performance%2Dbased%20sizing%20option%20in%20Azure%20Migrate%20assessments%20helps) |
| **as on-premises (as-is) sizing** (按本地配置定规格) | "You can get sizing recommendations based on performance history (to optimize resources as you migrate), or based on on-premises machine settings without performance history." | 按本地配置定规格就是不看实际用量，照服务器现在的配置在 Azure 上找一样大的规格。没有性能数据时用它。 | [Microsoft, 2022, "Sizing recommendations" section, para. 1, sentence 2](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#sizing-recommendations:~:text=You%20can%20get%20sizing%20recommendations%20based%20on%20performance%20history) |
| **database assessment** (数据库评估) | "Using database assessments, you can assess the readiness of your SQL Server data estate for migration to Azure SQL Database, or Azure SQL Managed Instance." | 数据库评估就是专门检查 SQL Server 数据库能不能搬到 Azure SQL，并给出推荐目标和阻碍项。服务器评估管机器，它管数据库。 | [Microsoft, 2022, "Readiness and suitability analysis" section, para. 2](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#readiness-and-suitability-analysis:~:text=Using%20database%20assessments%2C%20you%20can%20assess%20the%20readiness%20of) |

## [Prioritize workloads and finalize the migration plan](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#prioritize-workloads)

![Diagram: Prioritize workloads and finalize the migration plan](media/prepare-for-cloud-adoption-with-a-data-driven-plan-3.png)

| Term | Definition | 中文解释 | Source |
|---|---|---|---|
| **blocker** (阻碍项) | "Before you migrate, review and mitigate any compatibility issues or unsupported features that might block the migration." | 阻碍项就是会让迁移做不成的问题，比如不兼容或 Azure 不支持的功能。迁移前要先找出来并解决。 | [Microsoft, 2022, "Evaluate gaps and blockers" section, para. 1, sentence 3](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#evaluate-gaps-and-blockers:~:text=Before%20you%20migrate%2C%20review%20and%20mitigate%20any%20compatibility%20issues) |
| **workload prioritization** (工作负载优先级排序) | "After you've collected information about your inventory, you can identify which applications and workloads to migrate first. ... To prioritize migration order, consider factors such as complexity, time-to-migrate, business urgency, production considerations, compliance, security requirements, and application knowledge." | 优先级排序就是决定哪些应用先迁、哪些后迁。看复杂度、耗时、业务紧急程度、合规等因素，一般先迁简单、风险低的。 | [Microsoft, 2022, "Prioritize workloads" section, paras. 1 and 2](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#prioritize-workloads:~:text=After%20you%27ve%20collected%20information%20about%20your%20inventory%2C%20you%20can) |
| **migration plan** (迁移计划) | "Create an effective cloud migration plan that includes detailed information about the applications you want to migrate, application and database availability, downtime constraints, and migration milestones." | 迁移计划就是写清楚要迁哪些应用、它们能停多久、各阶段什么时候完成。整个迁移按它来执行。 | [Microsoft, 2022, "Finalize the migration plan" section, para. 2](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#finalize-the-migration-plan:~:text=Create%20an%20effective%20cloud%20migration%20plan%20that%20includes%20detailed) |
| **migration wave** (迁移批次（波次）) | "To improve your odds of success, plan a series of subsequent waves of migrations. Identify a small set of prioritized workloads to migrate, test, and release to production in a two-week sprint." | 迁移批次就是把要迁的系统分成一批一批，每批在一个短周期里迁完、测完、上线。先迁小批积累经验，后面的批次越来越大。 | [Microsoft, 2022, "Output of the exercise" section, para. 3](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#output-of-the-exercise:~:text=To%20improve%20your%20odds%20of%20success%2C%20plan%20a%20series%20of) |
| **recovery time objective (RTO)** (恢复时间目标) | "Recovery time objective (RTO): The maximum acceptable time that an application can be unavailable after an incident." *Note: Quoted from a table row (cells joined). This page names RTO under "Evaluate gaps and blockers" but does not define it.* | 恢复时间目标就是出事后一个应用最多可以停多久。迁移计划要保证停机时间不超过它。 | [Microsoft, n.d., table 2 (Term, Definition), row 6](https://learn.microsoft.com/en-us/azure/well-architected/reliability/metrics#:~:text=The%20maximum%20acceptable%20time%20that%20an%20application%20can%20be%20unavailable) |
| **maintenance window** (维护窗口) | "Build a migration roadmap. Declare a maintenance window to migrate your applications and databases with minimal to zero downtime, and to limit the potential operational and business impact during migration." | 维护窗口就是事先宣布的一段可以动系统的时间。迁移安排在这段时间里做，停机最少，对业务影响最小。 | [Microsoft, 2022, "Finalize the migration plan" section, para. 4](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#finalize-the-migration-plan:~:text=Build%20a%20migration%20roadmap.%20Declare%20a%20maintenance%20window%20to) |
| **post-migration testing** (迁移后测试) | "A post-migration testing plan should include functional, integration, security, and performance testing and use cases." | 迁移后测试就是搬完以后检查功能、对接、安全和性能是否正常。确认数据和应用都没问题才算迁完。 | [Microsoft, 2022, "Finalize the migration plan" section, para. 3](https://web.archive.org/web/20220804114917/https://docs.microsoft.com/en-us/learn/modules/cloud-adoption-framework-plan/4-exercise-digital-estate-assessment#finalize-the-migration-plan:~:text=A%20post%2Dmigration%20testing%20plan%20should%20include%20functional%2C%20integration) |
