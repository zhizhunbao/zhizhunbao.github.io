# CST8913: rules and allowed topics

The course slides copy official pages, sometimes old versions, sometimes with mistakes or gaps. So this folder follows **the official Cloud Adoption Framework** (decided 2026-10-20, after one page per copied source turned out scattered): one page per CAF phase, plus the basics and the tools the course uses, which sit outside the framework. The slides decide only what is covered and how deep, never how the pages are split. This README is the contract for the folder. `build_site_pages.py` (cloud notes repo, `courses/cloud-migration-cst8913/review/midterm/`) reads it and refuses to build a page that breaks it. This README is not published (`docfx.json` excludes `**/README.md`).

## Folders

- `index.md`: the overview, study by week (lab, concepts, lecture pages).
- `lectures/`: the source pages below (one per source the lecture slides copy) and their figures in `lectures/media/`.
- `labs/`: one page per lab: each concept as a question, answered with my lab text (from `review/midterm/site/labs.json`), linked to the lecture pages; images in `labs/media/`.
- Pages in this folder itself other than `index.md` are redirect stubs for the old URLs (the pages sat here before 2026-10-19).

All three are generated by `build_site_pages.py`, which also writes the CST8913 part of `../toc.yml`.

## Rules

1. **One page per CAF phase.** Each page in `lectures/` is one row of the table below: its file name, title (H1) and main source are fixed there. The CAF pages are Cloud Adoption Framework (the overview), Strategy, Plan, Ready and Adopt; Azure Architecture Center holds the reference architecture the course uses; the basics and the tools keep one page per source. Govern, Secure, Manage and the Well-Architected Framework have no page until the course covers them. `index.md` is the overview; no other page is allowed.
2. **Sections are the sections of the framework.** The headings of a page are the parts listed for it below, word for word, in that order. On a CAF page they are the first-level sections of the 2022 table of contents (commit a5351162), in its order; a part the course has not covered is a placeholder ("To be added.") with no link, figure or table, and the course's own parts sit under the section they belong to as H3 (the spec's `phase`). Each covered part links the official page it follows. Part names may be short forms of the source headings. Draw to level 2, and to level 3 only where the course covers it.
3. **One figure per section.** Every part section has exactly one figure, drawn by us in draw.io (no copied images, so terms can be marked).
4. **Key terms are framed on the figure.** A term worth learning is on the figure with a thick amber frame.
5. **The table holds only framed terms.** Each section's table lists exactly the framed terms of its figure, in figure order. A term that is not on the figure is not in the table. Each term is defined on one page only, in the first section where it is framed.
6. **Definitions are quotes from the source** (or another official page), with an in-text citation linked to the section and paragraph. Where no official text exists: my own words, marked "My own words".
7. **No slide text and no lab handout text is published.** Lab pages (`labs/`) are my own work: each concept the lab needs is asked as a question in my words and answered with what I wrote in my submitted lab (decided 2026-10-19). My name, student number, email and repository names never appear.
