# 1.1 Parallelism

Sources: [CS2023 Body of Knowledge, PDC-Programs, topic 1, p. 157](https://csed.acm.org/wp-content/uploads/2024/04/3.1-Body-of-Knowledge-1.pdf#page=157).

Parts:

- a. Declarative parallelism: Determining which actions may, or must not, be performed in parallel, at the level of instructions, functions, closures, composite actions, sessions, tasks, and services is the main idea underlying PDC algorithms; failing to do so is the main source of errors. (See also: PDC-Algorithms)
- b. Defining order: for example, using happens-before relations or series/parallel directed acyclic graphs representing programs.
- c. Independence: determining when ordering does not matter, in terms of commutativity, dependencies, preconditions.
- d. Ensuring ordering among otherwise parallel actions when necessary, including locking, safe publication; and imposing communication – sending a message happens before receiving it; conversely relaxing when unnecessary.
