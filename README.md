# Peng Wang Knowledge Base

Source of <https://zhizhunbao.github.io>. Same setup as Microsoft Learn: Markdown in a GitHub repository, built with [DocFX](https://dotnet.github.io/docfx/), published by GitHub Actions to GitHub Pages.

- Pages: `docs/**/*.md`, each with YAML metadata (`title`, `description`, `ms.date`).
- Navigation: `docs/toc.yml` is the top bar; each section folder has its own `toc.yml` for the left sidebar.
- Figures: each `media/<name>.png` figure has its source in `figures/`, at the same path without `docs/` and `media/` (`docs/cloud/azure/migration/media/plan.png` comes from `figures/cloud/azure/migration/plan.html`). A source is one self-contained HTML file (inline CSS, no external assets; each box is one line). To change a figure, edit its source and render it from the repo root with `python figures/shot.py <source.html> <docs/.../media/name.png>` (Playwright Chromium, viewport 1400x900, scale 2, screenshot of `#fig`). `figures/` is outside `docs/`, so it is not built or published. All Azure figures and the section Overview figures have sources; other older figures, drawn in draw.io, have none yet. Long group names are never shortened or wrapped; a figure too wide for one row splits its groups over two rows, in order, and all groups take the width of the widest group title (a short script at the end of the source sets it, as in `figures/networking/ccna/ccna.html`).
- Config: `docs/docfx.json`. Look: `docs/templates/kb/`: the page shell follows a Microsoft Learn article page (two header bars, TOC tree, breadcrumbs, In this article, Light/Dark/Auto) and is styled by the open-source Atlas Design System (`public/atlas.min.css`, MIT); `public/kb.css` holds the Learn-only bits measured from Learn, `public/kb.js` draws the navigation from DocFX toc.json and searches index.json; header items that do not fit on one line go into a "More" menu at the end, as on Learn. Images under `media/` show at half their pixels (figures are exported at 2x), except `.webp` screenshots (project pages), which fill the article width.
- Quizzes: pages are Markdown only, with one exception for quizzes. A quiz page is a Markdown page whose paragraph `[Start the quiz](wN.json)` links a JSON file of questions (`{ "questions": [{ "stem", "zhStem", "options", "answer", "zhTerm", "definition", "zh", "keys", "verbs", "zhVerbs" }] }`: a scenario in my own words and its Chinese, the answer's official definition and its translation); `public/quiz.js` replaces that paragraph with the questions: click an option to check it, then the right option turns green (a wrong pick red), and the question in Chinese and the answer's definition in English and Chinese show, marked like the term tables. Without JavaScript the link still opens the data. No page uses it at the moment (the CST8913 quiz pages were removed with the course pages on 2026-10-24).
- Term tables (`Term | Definition | 中文翻译 | Source`): the Chinese column translates the English definition. Key words are bold in the same order in both cells, and `kb.css` gives the n-th bold of each cell the same colour. `public/marks.js` (called from `kb.js`) puts the verb (谓语) of each English definition and of its Chinese translation with a red wavy underline, from `media/<page>.grammar.json` (`{ term: { "verbs": [[phrase, skip], ...], "zhVerbs": [[phrase, skip], ...] } }`: the verb phrases in order, `skip` passing over earlier matches, one Chinese entry per English one, contractions such as it's left out); quizzes use the same marks. The Git and GitHub pages under Programming carry such files (moved from the CST8913 pages on 2026-10-24).
- Preview locally: double-click `start-knowledge-base.bat` (or run `python docs/templates/kb/watch.py`) and open <http://localhost:8080>. It rebuilds after any change under `docs/` (a full build, about a minute for 4,300 pages; docfx 2.81 has no incremental build) and the open page reloads itself (plain `docfx --serve` builds only once). The preview builds into `_site` at the repo root (ignored by git), outside `docs/`: built into `docs/_site` a full build took 390 s instead of about 55 s (measured 2026-10-25). The script writes `docs/docfx.build.json` (ignored by git): `docfx.json` plus each page's last commit time, shown as "Last updated on MM/DD/YYYY HH:MM:SS". Building `docs/docfx.json` directly still works, with the date from `ms.date` only. GitHub Actions does the same two steps.
- Publish: push to `main`; `.github/workflows/docfx.yml` builds and deploys.

## Navigation rules

Content has official sources; section names are the common names of the field.

- Top bar (`docs/toc.yml`): Home and Projects first, then the sections in alphabetical order of their names. A section name is the common name of the field (AI, Algorithms, Security, UI/UX). It is not an official classification, so each section states the knowledge area of the ACM/IEEE-CS/AAAI Computer Science Curricula 2023, CS2023 ([Joint Task Force on Computing Curricula, 2024](https://doi.org/10.1145/3664191)), it maps to, as in the table below.
- Second level (second bar): one entry per official source, benchmarked against `Microsoft Azure` under Cloud. An entry must pass three tests: (1) it has one official documentation set; (2) that set has its own classification, which the third level follows; (3) it carries the name people use for it. So it is a product or platform (PostgreSQL, Python) or a standard or framework (WCAG 2.2, NIST Cybersecurity Framework), never an organization (OWASP, ISTQB). For a technology the entry is named by the technology itself (Docker, Kubernetes, GraphQL, Claude, Linux, HTML, Arm, x86), not by its documentation set ("Docker Docs", "Claude Platform", "The Linux Kernel documentation", "HTML Standard") or a suffix ("Fluent 2 Design System"); the index page names the documentation set, word for word, as the official source. Standards and frameworks keep their full names, and Microsoft entries keep the Microsoft name (Microsoft Azure, Microsoft Foundry). Protocols defined in RFCs stay under RFC Series in Networking, one third-level page per RFC (RFC 9110 HTTP Semantics), with all its sections. A course decides which topics of a source get pages (only the ones I study, in the source's own order and titles), never their names, order or content. Alphabetical order, Overview first. The third level follows that source's own classification and the fourth level its sub-classification, never alphabetical by our choice (only the top bar and the second level are alphabetical). Their order depends on the source: (1) numbered sources keep their numbers (WCAG 2.2, ISTQB CTFL, CCNA exam topics); (2) unnumbered sources whose lists have an order of their own keep it and get numbered in it (Dev.java Learn, APG Practices and About); (3) sources that only list alphabetically, as an index, get a logical order we choose for that source (a component library from simple to complex, a specification by dependency, tutorials in learning order), with no group level added, and the section's index page says how the source orders it, how we do and why (APG Patterns). Comparisons between sources come after. Sources are current and cited in APA; not roadmap.sh or similar community sites, which cannot be cited. Exception: Math uses the CS2023 knowledge units of MSF as its second level (still in alphabetical order), because they do not date. Algorithms, like AI, has CS2023 itself as an entry (CS2023 AL, its units in CS2023's order), next to the NIST Dictionary of Algorithms and Data Structures, the reference for definitions: its areas, each listing all its entries with their type (algorithm, data structure, classic problem, algorithmic technique, definition) and a link to the definition, not given pages of their own.
- Courses are not second-level entries either. The course pages under Cloud (CST8912, CST8913, CST8914) were removed on 2026-10-24; only the two Git pages moved, to Programming.
- Each section also has its CS2023 knowledge area as a second-level entry, `CS2023 <code>` (CS2023 AI, AL, AR, DM, FPL, GIT, HCI, NC, OS, PDC, SDF, SE, SEC, SEP, SF, SPD; Math keeps the MSF units as its second level): the units in CS2023's order, numbered, and their topics with CS2023's numbering, tier (CS Core, KA Core, Non-core) and parts, as the checklist of what the field covers. Where CS2023 numbers oddly (FPL-Analysis starts at 4, OS-Advanced-Files restarts at 1 for Non-core, SF-Evaluation has two topics 7), the numbers are kept.
- A new term whose official source is a documentation set the site doesn't have yet: (1) cache the set's table of contents and the pages the term needs (`design-refs/official-docs`); (2) in the entry's folder README, sort the table of contents into parts that hold terms and parts that don't (release notes, how-to, tutorials, reference lists, links), and number the term parts once (`N.`), grouped by concept where the official groups mix both; (3) add the term on the page where the source defines it. The plan is correct information, so every planned group is on the site from the start (figure group, menu entry, page naming the official parts its terms come from, "Not written yet" until a term arrives); the parts without terms stay only in the cached table of contents, and nothing useless is copied onto the site (first done for SQL Server, 2026-10-26). The table of contents lists articles, not terms: figures box only terms.
- A planned section or second-level entry has only its index page (name, CS2023 mapping or official source) until content arrives.
- A section's Overview (its `index.md`, Hardware first, 2026-10-25) follows the Azure topic overview (`docs/cloud/azure/README.md`): H1 is the section name, then `## Classification` (one figure in `media/`: the section name framed top left, its second-level entries grouped by kind in dashed groups, names only, no numbers), `## Glossary` (the term table: first row the section name, then one row per group in figure order, group names exactly as in the figure; completing a figure completes these rows), `## Coverage` only where certifications cover the section (`Certification | Skill area`, one row per skill area of each exam, linked to its study guide anchor; AI: AI-901 and AI-103), and `## References`. No intro sentence and no list of sources: the figure and the references already give them.
- Cloud is organised by the Azure documentation categories and certifications, and `docs/cloud/azure/README.md` lists the CS2023 knowledge units it maps to.
- Courses get no top-level section. What a course teaches lands in the section of its field.

## Content rules (the site is public)

- No lecture slide text, no lab answers.
- Definitions are quoted from official documentation (Microsoft Learn is CC BY 4.0) with an APA reference that names the section and paragraph and links the `#anchor`.
- Content that exists only in course materials is rewritten in my own words, without quotation marks.
- Cloud courses are in progress: no links to coursework code until grades are final. No student number anywhere.
- Never use the middle dot as a separator.
